# 中文口语法条检索：STARD研究起步

状态（2026-11-03）：已阅读官方论文、仓库说明及BM25示例源码；尚未下载完整数据、创建研究环境、运行基线或获得新的实验成绩。研究资料及后续产物均放在本D盘项目内。本文是研究起步记录，不表示方法创新已经成立。

## 现在先学什么

先理解“输入一句咨询，输出相关条文的排序”。STARD的官方说明列出1,543个咨询问题和55,348条候选条文；一个问题可能对应多条材料。它测检索，并不能证明最终回答正确或条文必然适用个人。来源：[论文](https://aclanthology.org/2024.findings-emnlp.625/)、[官方仓库](https://github.com/oneal2000/STARD)。

先看论文摘要、任务定义、实验部分与附录B/C。公式可以随后学，不要求先理解训练全过程。重点回答：问句从哪里来、哪些条文算相关、如何评分。

## 已核对的复现差异

- 仓库README将示例分为train/dev，比例4:1；论文中Dense-STARD等训练模型使用五折交叉验证。不能把示例dev的一次成绩称为完整论文复现。[README](https://github.com/oneal2000/STARD/blob/main/README.md)、[论文第6节](https://aclanthology.org/2024.findings-emnlp.625.pdf)。
- 论文附录B说明BM25采用Pyserini；仓库`src/BM25`是自写实现。其示例默认topk=3，用jieba分词，按条文名称收集文档及匹配相关材料。这与本项目实现也不同；复现时须分别核对分词、参数、重名条文、排序和候选范围。[示例源码](https://github.com/oneal2000/STARD/blob/main/src/BM25/test.py)、[BM25实现](https://github.com/oneal2000/STARD/blob/main/src/BM25/BM25.py)。
- 作者安装说明使用Python 3.9，并列出较旧依赖。README说单独安装torch，实际requirements仍包含它，不能直接把整份依赖装进现有生产环境。[依赖文件](https://github.com/oneal2000/STARD/blob/main/requirements.txt)。
- 作者的数据声明称数据已匿名化并采用MIT许可；实际使用时保存声明、许可和来源，单独核对下载版本，不能据此推断本项目原资料库也自动获得相同许可。[数据声明](https://github.com/oneal2000/STARD/blob/main/Data%20Statement.md)。

## 先弄懂三个分数

以下为自编数学例子：某题有3条标注相关材料，前5名只找回其中1条，且它排第2。

- Hit@5：有没有找到至少一条？本题为1。
- Recall@5：应该找回的材料找回多少？本题为1/3。
- MRR@5：第一条相关材料排多前？本题贡献1/2；超过5名仍未出现则为0。

批量评测还要明确如何平均、如何处理无结果及重复材料。不能把项目“命中题数”直接当作论文Recall，也不能将Recall当作回答正确率。[作者示例评分代码](https://github.com/oneal2000/STARD/blob/main/src/BM25/test.py)。

## 下一阶段的具体交付

1. 固定作者仓库提交、数据与许可文件校验和；只统计数量、ID完整性、重复、训练/评测交集，先不阅读评测逐题答案。
2. 建立独立研究目录和环境。先做示例实现的运行验证，明确标记“仓库示例基线”；按论文协议核对后才称“论文复现”。遇到缺少参数或划分信息就记录缺口。
3. 输出一份可重复运行的基线记录：代码/数据版本、候选库、划分、分词和参数、指标定义、耗时，以及与论文不一致之处。
4. 基线可信后，再选一项改进做对照。每次只变一处，保留全部实验结果，包括未改善和退步的结果。

正式研究方向暂定为“中文口语表达变化下的法条检索稳定性”，新颖性待进一步查文献。不同说法若来自同一个原始问题，必须成组划分，避免原句进训练、改写句进测试。改变关键事实的句子不能直接沿用原相关条文标注；需要人工核对。

现有项目dev用于开发、holdout只看汇总、user10由用户运行的约定继续有效。反复用于选方案的题不能再宣称未接触的盲测；人工标注和新盲测不能由AI自行生成后冒充完成。STARD语料与生产库独立，不覆盖现有Qdrant集合或法条快照。
