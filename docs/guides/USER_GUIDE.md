# 安装、使用与排错手册

本手册面向第一次使用本项目的人。先按顺序完成安装，再看“怎样提问和看结果”。命令在 **Windows PowerShell、项目根目录**执行；示例不包含作者电脑的解释器或资料路径。

当前定位是本地法律资料检索、材料阅读与事实核对。默认回答许可限制模型直接判定提问者违法、应赔多少钱或能获得什么诉讼结果；检查仍可能漏检或过度拦截，不能当成可靠的个案判断。依据卡片与所存快照一致，也不等于该条现在仍有效或适用于你的事情。

## 使用前先看：能做到哪里

正式开源应做到：已知的严重工程问题先修复，支持环境、安装方式和常见故障处理有据可查，未完成的验证如实列出。不能用一段免责声明代替修复，也不能因为测试通过就承诺软件没有任何问题。

- **不保证所有问题都能处理**：资料可能缺失，口语可能没匹配上，正确条文也可能没有进入前列或送模预算。遇到资料不足、范围不符或回答校验失败时，系统可能只给候选、降级或拒绝展示正文。
- **不保证所有结果都正确、完整或适用**：法规可能存在修订、过渡规则和例外；来源、条号与摘录核对正确，不等于适用于提问者。模型没有作出结论，也不表示需要核对的事实已经列全。
- **不保证所有设备和软件版本都兼容**：已验证的是记录中的Windows、64位CPython 3.12及指定依赖/模型；其他操作系统、Python、显卡、驱动或更新后的模型需要另外验证。
- **不把演示或题集成绩当作全部能力**：某批题的命中数、一次问答成功或单元测试通过，只证明相应检查，不能推成“任何问题都能答”。

目前哪些已实现、已验证、待验证或仍有缺口，以[开源准备记录](OPEN_SOURCE_READINESS.md)为准。使用时出现下列情况，先按“常见问题与故障排查”检查；公开反馈前匿名化，不上传原始私人咨询。

## 一、先确认拿到哪些文件

需要代码、与代码兼容的数据包、Python、Ollama及两个模型、Qdrant。这几部分不是同一个下载包：

- **代码及原创文档**：适用根目录MIT许可。
- **法规及案例数据**：看每份来源与使用范围，不能因为代码MIT就把整份网页、附件或编辑摘要当MIT资料。本地现有资料尚未完成公开包筛选；目前没有已验收的公开数据包下载地址。
- **模型、Python依赖、数据库程序**：按各自官方渠道和许可安装，不把开发者的模型目录、虚拟环境或数据库卷直接打包上传。
- **运行产物**：会话、原始回答、评测明细、缓存、日志、令牌、本机配置不随代码发布。

在当前维护者工作区，可以使用已核验的本地数据；外部用户若只有代码、缺少配套数据，应先完成来源核对及现有采集流程，不能把空库启动成功当成完整安装成功。公开包待办见 [开源准备记录](OPEN_SOURCE_READINESS.md)。现有加载器核对原件和哈希，不能随意删掉原始快照只保留解析JSON。

## 二、准备Python与依赖

当前实测环境是 **64位CPython 3.12、Windows**。不是MSYS Python，也没有完成Linux/macOS整套安装验收。

在项目文件夹的空白处打开PowerShell。先核对Python：

```powershell
py -3.12 -c "import sys; print(sys.version); print(sys.maxsize > 2**32)"
```

应显示3.12和`True`。没找到`py`时，先安装官方64位Python 3.12，或用你实际安装的完整解释器路径代替`py -3.12`。

然后创建项目自己的环境，无需激活脚本：

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements-local.txt
$projectPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
[System.IO.File]::WriteAllText((Join-Path $PWD '.local-python-path.txt'), $projectPython)
```

`.local-python-path.txt`只写这台机器的Python路径，不提交Git。不要把别人的文件照搬过来。虚拟环境也应本机创建，而不是复制作者的`.venv`或`.local-deps`。具体原理见 [Python venv官方说明](https://docs.python.org/3.12/library/venv.html)。

维护者现有环境保留`.local-deps`兼容路径；新安装用上面的虚拟环境即可。如果同目录存在旧`.local-deps`，它会被优先加载，隔离验证时必须使用不含该目录的独立代码副本。

## 三、准备本地模型

从 [Ollama官网](https://ollama.com/download)安装。默认模型标签为：

- 对话：`qwen3:4b-instruct-2507-q4_K_M`。
- 向量：`qwen3-embedding:0.6b`。

已有Ollama服务时先检查`ollama list`，不要结束其他项目正在使用的服务。缺少模型时，在该服务对应的目录下载：

```powershell
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama pull qwen3-embedding:0.6b
ollama list
```

下载需要网络、磁盘空间和时间。项目不会偷偷改用云模型，也不会自动下载更大模型。命令说明见 [Ollama CLI](https://docs.ollama.com/cli)。

希望新装模型放在项目D盘目录时，先由你在托盘退出自己启动的Ollama，再在项目根目录的新PowerShell窗口执行：

```powershell
$env:OLLAMA_MODELS = Join-Path $PWD 'data/ollama_models'
$env:OLLAMA_HOST = '127.0.0.1:11434'
$env:OLLAMA_NO_CLOUD = '1'
ollama serve
```

保持这个窗口，在第二个窗口下载模型。下载由运行中的服务落盘；只给客户端设置`OLLAMA_MODELS`不会移动已有模型或改变已有服务的目录。不要为了本项目关闭你不能确认归属的服务。[Ollama目录及Windows环境变量说明](https://docs.ollama.com/faq)解释了生效时机。

启动器与模型适配器统一按以下顺序解析目录：显式`OLLAMA_MODELS`，已有项目模型，已有用户模型；新安装默认`data/ollama_models`。解析目录不会搬移文件。相同模型标签更新后的digest也可能变化，不应无意更新模型后仍宣称与旧评测完全可比。

## 四、准备Qdrant

默认地址是`http://127.0.0.1:16333`。当前维护者使用Docker中的Qdrant及本机网关；有现成服务可直接复用，不必再创建第二个数据库。只对外绑定本机环回地址。

新安装按 [Qdrant本地官方指南](https://qdrant.tech/documentation/quickstart/)准备Docker和持久存储。本机实测Qdrant版本为1.18.2；不要直接升级现有数据库。新容器可把主机`127.0.0.1:16333`映射到容器`6333`，这样不需要另建网关；或使用已有6333服务并在**启动项目的同一窗口**设置：

```powershell
$env:QDRANT_LOCAL_URL = 'http://127.0.0.1:6333'
```

Docker的数据库持久存储不是项目的`data/local_index`。Windows目录挂载与命名卷由Docker管理，官方提示Windows可能需要命名卷；若要求所有数据在D盘，先核实Docker磁盘和卷的位置，不能仅凭PowerShell在D盘就认为卷也在D盘。本轮没有替新用户搬动数据库卷，也没有完成全新Docker安装验收。

可在本机访问所选地址的`/healthz`确认200响应。已有6333/16333占用时先确认服务身份，不要清空数据库、删除集合或结束陌生进程。

## 五、启动前先自检

新PowerShell窗口需要重新取得解释器变量：

```powershell
$projectPython = (Get-Content -LiteralPath .local-python-path.txt -Raw).Trim()
& $projectPython -B -X utf8 run_local.py --check
```

自检读取依赖、语料及本机服务状态；不调用对话模型、不生成向量、不建集合、不启动或停止服务。它会读取资料原件进行一致性核验，因此不只是检查文件名。

- `python_ok/dependencies_ok/data_ok`：解释器、依赖、资料是否能正常加载。
- `coverage`：实际加载的规范数、案例摘要数和检索段数；不是现行性或完整法律覆盖证明。
- `ollama_connected/models_ready`：模型服务可达、两个默认标签齐全。
- `qdrant_ready`：数据库健康接口可达，不代表当前批次已完成同步。
- `web_state`：`free`为空闲，`same_workspace`为本目录已有Web，`occupied_or_unverified`表示端口占用且归属未确认。
- `ready`：上述启动前条件全部满足。退出码0为满足，2为仍缺条件，1为配置无效或自检无法执行。自检不会打印本机访问令牌。

这里的`ready`是启动条件汇总；真正可用的混合检索还要看网页的`database.ready=true`与`index.state=ready`。

## 六、启动、复用、停止与更新代码

双击`start_local.cmd`，或在终端运行：

```powershell
& $projectPython -B -X utf8 run_local.py
```

浏览器打开`http://127.0.0.1:18765/`。保持启动窗口，查看页面模型与索引状态。

- 同目录已有带身份信息的Web时，只复用，**不重新加载代码**。
- 其他目录、未知服务或旧版缺少身份字段占用18765时，报错并保留原服务。回到原启动窗口确认归属后停止；不要照着旧`server.pid`强制杀进程。
- 本次新建的Web可以用启动窗口`Ctrl+C`停止；已有Ollama和Qdrant继续运行。关闭/重载Web会结束其内存会话，先保存需要的结果。
- 改源码后，停止原项目Web并重新启动；再次双击复用旧进程不算加载新代码。
- `--no-browser`不自动开网页；`--once --no-browser`启动后让Web留在后台，适合维护者。新手建议保留窗口，不必使用后台模式。

有向量缓存时仍需解析资料、加载缓存并核对Qdrant，本机大缓存加载约分钟量级。新资料没有缓存时还需逐段生成向量，时间取决于机器和资料量，不能承诺几分钟完成。启动器等Web接口最多180秒；超时看日志，不能反复点击重建。Web接口出现不代表后台入库已结束。

数据库或向量查询暂时异常时，当轮明确降级为词面检索；已有入库就绪标记不会被永久写坏，恢复后下次查询可自动恢复。降级结果不能算正常混合检索验收。

## 七、怎样提问、怎样看结果

描述发生了什么、时间地点、双方身份、合同约定和现有证据。不要提交身份证号、住址、账户等无关隐私；使用匿名表述。

页面回答保留“问题理解、处理方向、注意事项、下一步”四个标题。当前“处理方向”用于原文节选及还需核对的问题，不替你判责、算确定赔偿或决定诉讼主张。列出的事实问句也不保证穷尽全部适用条件、例外和但书。

查看结果时按这个顺序：

1. 看是否有模型、数据库或领域降级提示。
2. 阅读依据卡片上的条号、原文、采集版本与官方来源；重要事项核实现行文本及适用时间。
3. 查看“检索候选”前8条；带材料编号并标明已送模的，才是本轮模型实际读到的材料。预算内默认请求4条，过长材料可能整条舍弃。
4. 展开“更多候选”。这里用于人工继续查找，没有送入模型，不能把“页面有这条”当作“模型依据过这条”。
5. 若整段被拦截，页面保留候选供继续核对。拦截说明回答未通过检查，不代表事情没有法律依据，也不证明所有放行回答都适用。

条号、期限、倍数和金额等对不上材料，或出现超出阅读许可的自由结论时，回答仍会拦截。原始错误保留用于评测，不靠隐藏错误宣称模型从不出错。详细边界见 [材料阅读许可](MATERIAL_READING.md)与[展示说明](DISPLAY_CANDIDATES.md)。

模型和向量查询走本机服务，但不能把默认Web称为完全离线：首次安装/下载及缺少特定专项时的官方文本兜底可能联网，后者由默认Web装配国家库抓取器并保存独立缓存。直接构造的离线服务与默认Web行为不同，详见[项目阅读指南](PYCHARM_PROJECT_READING.md)。本轮自检不运行问答兜底，也不访问法规网站。

## 八、更新资料与备份

保留官方来源、采集版本、原始快照、哈希和解析产物。新增网站格式需解析适配和核验，不能把任意文件扔进去就算已入库。先读 [知识库管线](QDRANT_KNOWLEDGE_PIPELINE.md)，再决定是否运行采集。

双击`update_knowledge.cmd`或运行`python -m local_rag.index`会做资料加载、向量复用/生成和数据库写入，不是只读检查；使用项目解释器。命令行更新不替运行中的Web刷新内存，网页需使用“加载新资料并入库”，或在确认源码版本后重启。

备份代码版本、数据原件/产物/清单和数据库存储；模型可按官方渠道重新取得，向量缓存可重建但耗时。需要删除时先核实归属，不能删除共享Ollama模型或其他项目Qdrant集合。数据、缓存和评测报告的发布范围见开源准备记录，不把私有回答当演示数据上传。

## 九、常见问题与故障排查

- **找不到Python/uvicorn**：核对`.local-python-path.txt`指向本机3.12环境，在同一个解释器中安装依赖；不要换成系统默认MSYS解释器碰运气。
- **模型缺标签**：`ollama list`确认当前服务目录，再下载缺少的指定标签；项目不会杀掉它换目录。
- **18765已占用**：先回原项目窗口确认、停止或等待加载。端口探测和PID文件均不能授权结束某个进程。
- **数据库不就绪**：确认Docker、Qdrant、16333网关或显式配置地址；健康恢复后查询可以重试。只有尚未完成本批入库时才需要同步，不能把每次超时都当成应重建。
- **资料核验失败**：保留现场，核对数据包版本、原始快照和哈希，不修改条文来绕过校验。
- **长时间等待**：查看`data/runtime/server.log`和网页入库进度；该日志只用于本机排错，分享前检查隐私。不公开完整`/api/status`响应，其中含本机访问令牌。
- **被拦截/材料不相关**：先读候选与官方原文，补充缺失事实；重要事项咨询专业人员，不以反复提问取得的肯定措辞作为结论。

以下情况也需要区分，不能一概当成系统已经出错或已经正确：

### 页面打开了，为什么仍不能正常问答？

页面、模型、向量索引和数据库分别就绪。先运行`--check`，再看网页模型状态、`index.state`和`database.ready`。后台尚在生成向量时等待进度；模型未安装时核对标签；数据库不可达时检查原服务。不要只看首页200或“启动成功”就认为所有链路都可用。

### 正确法条在候选里，为什么正文没用到？

前8条及“更多候选”是人工查找入口；只有标明已送模的材料才进入本轮回答。默认请求4条，还受材料和整体输入预算限制。正确条文在页面出现但未送模，是当前能力限制；不要把候选展示命中等同于模型已读过，也不要直接提高参数来绕开预算。

### 没找到我要的条文，能说明没有相关规定吗？

不能。可能是资料没收录、口语未匹配、排序靠后或地域/专项范围不符。先查前8条和更多候选，核对资料覆盖，再补充时间、地域、身份及事件事实；仍不足时去官方来源继续检索。不能把本项目没有检索到当成不存在法律依据。

### 为什么不直接告诉我该赔多少、该怎么起诉？

当前回答模式是材料阅读与事实核对，适用判断还依赖未查明的事实和规则。它按许可提供可核对节选、事实问句及通用步骤；个案结论或无法核对的输出可能整段拦截。这是产品范围，并不承诺系统能替代专业判断。检查也可能误拦或漏检。

### 为什么同样的问题，两次回答不同？

模型生成、对话历史、资料/模型版本及当轮服务是否降级均可能影响结果。比较时先确认同一代码、资料、模型标签及digest、会话背景和检索模式。不能用反复刷新得到的一次肯定回答替代核验；需要复现问题时记录这些条件。

### 运行很慢、内存不足或显存不足怎么办？

先区分正在加载缓存、生成向量还是生成回答，查看网页进度与本机日志；检查磁盘空间和资源占用，关闭自己不需要的任务，避免重复启动/重建。当前没有覆盖全部硬件的最低配置或耗时保证。不要擅自换模型后仍把旧评测当作新模型的成绩，也不要删除资料原件来腾空间。

### 可以完全离线用，或者直接给局域网其他人访问吗？

默认Web有按需官方文本兜底，首次依赖与模型下载也要联网；不能承诺完整流程始终离线。当前服务面向本机环回访问，没有完成公网或多人部署验收。不能只把监听地址改成`0.0.0.0`就当成受支持的共享服务。

### 反馈问题时应该提供什么？

提供代码版本、操作系统、Python版本、模型标签、执行步骤、预期和实际表现、是否降级及匿名化后的错误类型。检索问题可提供不含身份信息的复现问句、候选条号和来源链接。日志只摘取必要片段并检查隐私；不公开完整`/api/status`、访问令牌、密钥、会话编号、私人原始回答或包含个人信息的截图。当前还未公布专用漏洞私密反馈渠道；安全问题不要把可利用细节或秘密直接贴到公开讨论中，正式发布须先补齐反馈方式。

普通使用无需运行评测。维护者可运行`& $projectPython -B -X utf8 scripts/run_workspace_tests.py`；检索改动还需按AGENTS执行measure/eval、保留holdout汇总边界。

## 十、已经实测什么，还差什么

启动保护、隔离依赖安装和本机复验的最新证据见 [开源准备记录](OPEN_SOURCE_READINESS.md#本轮工程整理)。隔离虚拟环境仍运行在同一台Windows机器，使用本地资料副本及既有模型/数据库，不能冒充另一台电脑从零下载、入库的验证。

正式发布前仍需冻结公开数据清单、完成资料范围及Git历史隐私复核、用最终发布包走通新用户安装。现有检索与回答评测有已知遗漏及拒答，不能把“开源正式版”等同于“任何法律问题都能正确处理”。
