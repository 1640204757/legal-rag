# Qdrant 知识库：阅读与更新

## 现在接的是什么

Python 负责下载解析、核验、调用 Ollama 生成向量、检索和问答。Qdrant 保存资料向量及来源字段。

现有 `qdrant` 容器才是数据库，原存储挂载为 `<宿主机原有Qdrant存储目录>`。新增的 `legal-rag-qdrant-gateway` 是 nginx 转发入口，不是第二个向量数据库：

`本地 Python → 127.0.0.1:16333 → nginx:8080 → 原 qdrant:6333`

原数据库没有发布主机端口，Windows 的保留端口范围包含 6333，因此使用 16333。网关只绑定本机环回地址；配置见 `deploy/qdrant-gateway.conf`。原有其他项目集合保留。

关 Docker 前已实际写入 2575 段（9 部规范、6 个案例发布稿摘要），集合为 `legal_rag_4e63b7280cb4_1024`。这是当时的实测记录，不是 Docker 关闭后的在线状态。

## 日常启动

1. 打开 Docker Desktop，等待引擎启动。
2. 启动现有 `qdrant` 和 `legal-rag-qdrant-gateway` 两个容器；不需要启动 RabbitMQ 或 Milvus。
3. 双击项目根目录 `start_local.cmd`，打开本地网页。
4. 右侧确认 Qdrant 已同步及段数。数据库不可用时明确显示降级为关键词检索，不能当作向量检索成功。

网页显示的同步状态记录最近一次同步结果，不是持续健康探测；实际查询失败后会降级。Docker 恢复后点击“加载新资料并入库”重新同步。

## 新资料如何接着使用

1. 确认官方来源、版本、可用范围与再利用条件。在 `local_rag/ingest.py` 登记支持的来源。
2. 按现有入口下载解析：`python -m local_rag.ingest`。原文、哈希和解析记录保存在 `data/library/`；隔离资料不进入检索。
3. 核对条号、来源、正文范围与缺口。新格式需要先增加解析适配，不能把任意 PDF、扫描件或裁判文书直接当成已核验条文。
4. 网页点击“加载新资料并入库”：重新从磁盘加载、复用或生成向量、写入 Qdrant。无需为相同格式新增问答代码。
5. 用新资料对应的问题及反例检查召回、引用与资料不足时的表现。

也可双击根目录 `update_knowledge.cmd`，或运行 `python -m local_rag.index --search "未参加工伤保险的待遇由谁支付"`。命令行入库不替正在运行的网页进程更新内存资料；网页已开启时仍需点击加载按钮。

直接运行 Python 模块时，设置 `PYTHONPATH` 为项目根目录和 `.local-deps`，解释器见 `.local-python-path.txt`。当前尚未迁移为 uv 项目。

## 代码阅读顺序

- `ingest.py`：取得资料和解析条文。
- `retrieval.py`：加载资料、向量缓存、BM25 与向量融合排序。
- `ollama.py`：本机嵌入与问答模型接口。
- `qdrant.py`：集合、幂等写入、批次过滤、召回内容一致性核对。
- `index.py`：独立入库命令。
- `app.py`：网页接口和资料重新加载。
- `service.py`：会话、检索、模型回答及输出检查。

`data/local_index/embeddings.json` 是向量复用缓存；Qdrant 是当前网页的向量查询后端，两者不是同一份存储。集合随嵌入模型身份和维数区分；语料变化按批次隔离，旧批次保留且不参与当前批次查询。重复导入相同资料不会重复增加当前批次点数。更换嵌入模型后需重新生成/入库，不能混用旧向量。
