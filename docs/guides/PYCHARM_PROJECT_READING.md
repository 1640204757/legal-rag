## 1. 打开什么

在 PyCharm 中选择 **Open**，打开整个 `<项目根目录>` 文件夹，不要只打开某一个 `.py` 文件，也不要把 `.venv` 或 `.local-deps` 当成项目根目录打开。

打开后，先阅读根目录的 [README.md](../../README.md)，再按本指南跟读代码。`.local-deps`、`.venv`、`data/local_index` 可在 IDE 中右键标为 **Excluded（排除目录）** 以加快索引速度，但不要删除 `.local-deps`。

- **资料入库链**：`ingest.py` / `catalog_ingest.py` 采集并切分条文 → 保存至 `data/library/` → `retrieval.load_corpus()` 校验加载 → `Retriever.build()` 向量化并缓存至 `data/local_index/embeddings.json` → `qdrant.py` 写入本地 Qdrant。
- **在线问答链**：前端提交 → `app.py` → `service.py` 先本地检索和地域硬降级检查 → 未降级时另取前8条与“更多候选”（`display`，只供页面展示）→ 可选官方目录最后兜底 → 原预算整条选择材料 → `ollama.py` 只选 `M1#1` 等完整句编号/短语 → `answer_assembly.build_final_answer()` 从材料原文确定回填 → 原始引用、期限、金额与材料阅读许可检查 → `clean_display_answer()` → 返回前端。目录定位记录在 `official_fallback`，未抓到条文时不能生成目录引用卡片；`raw_answer` 保留模型原始选择、`final_answer` 保留校验器实际看到的装配文本，条文卡片仍保留原编号。每张依据卡片写明采集版本和未在线复核现行性。
- **评测旁路**：固定题集/哈希校验 → Web状态与模型摘要核对 → 当前Qdrant批次精确计数 → 生产 `Retriever.search()` → 独立命中判分；回答抽检再走独立内存 `ChatService` → 真实4B → 原始/展示结构审计 → 唯一运行目录。旁路不调用 `build()` / `sync()`，不写Qdrant，不修改原始法规。检索诊断尺子同样走这条旁路，另外只读 BM25 内存索引的完整排名，并发一次不带0.38阈值的只读语义查询。

`REMEDY_STRUCT_MARKERS` 识别“享有下列权利”“提出申诉”“准予毕业”“赔偿损失”“申请复核”等权利救济结构；`MISMATCHED_OFFICIAL_MARKERS` 识别证书无效收回、工作人员滥用职权或履职保密等容易错位的监管结构；`OFFICIAL_QUERY_KEYWORDS` 为原问句中的“部门/机关/工作人员/履职/履行职责/执法/调查/政务/伪造/假证/弄虚作假”设置豁免开关。开关只看原问句，不能被扩展词中的“有关机关”等内容反向触发。

未命中官方查询词时，条文先命中错位监管结构，`intent_factor=0.55`；否则命中救济结构，取1.35；其余为1.0。同条同时含两组结构时错位监管优先。原问句含任一官方查询词时，两种结构调节均关闭，因子统一为1.0。对从0开始的名次 `rank`，融合贡献为：

- 向量路贡献为 `(1.2 * intent_factor * scope_factor(i)) / (30 + rank + 1)`；只调整融合贡献，不修改原始相似度或BM25分数。
- `scope_factor(i)==1.0`、法名非空且该法尚不足两条提权时，词面原始BM25 `>=140.0` 获 `2.1 / (30 + rank + 1)`；`85.0 <= 分数 < 140.0` 仍为 `1.35 / (30 + rank + 1)`。两档共用 `boosted_title_counts`，同法第三条即使超过140也不再获高档。2.1用于多短语法定要件强匹配，可超过单路救济向量的1.62贡献系数；高分本身仍不证明法律适用。
- `scope_factor(i)==1.0` 且未获上述提权，但行号也在向量候选中、非空法名在向量前6名中未受范围降权的法名集合内，或者 BM25 `>= 35.0` 时，贡献为 `1.0 / (30 + rank + 1)`。
- 其余词面候选贡献为 `(0.25 * scope_factor(i)) / (30 + rank + 1)`。缺失或空法名不能获得2.1/1.35提权或同法印证；范围线索充足时精确双路共识不依赖法名。

`scope_factor()` 仅看原问句的小写形式和候选标题：未成年人保护/预防犯罪、工会、娱乐场所、归侨侨眷、三峡/水利水电/蓄滞洪工程、出国旅游、国企富余职工等七组专门法规，标题命中但原问句不含对应任一线索时取0.4，否则取1.0。出国旅游使用“出国/出境/境外/国外/领队”，国企安置使用“国有企业/国企/富余职工”；只看原问句，不能被扩展词放行。受限候选的词面权重固定为0.1，即使双路重合或BM25超过85也不能恢复高档，不为同法候选提供印证，也不计入超强锚点法名数。明确提及对应主体、地域或“KTV”等时恢复原规则；恢复不保证实际适用或必居首位。

两路贡献相加后先按 `(-score, index)` 得到 `ranked_all`。若 `len(boosted_title_counts) >= 2`，首轮按原次序每个非空法名最多选两条，超额条款放入 `overflow`，最终以 `selected + overflow` 回填后再截 Top-K；空法名不限流。候选不删除，分值不改，但多样性重排后的列表不保证分值全局递减。只有一个法名触发超强锚点时，直接保留 `ranked_all`，不限制同法多条。

`fuse_ranks(lexical, dense)` 的原两参数等权实现完全不变；新权重和多法名覆盖均在 `search()` 的混合分支内执行。向量未就绪、无合格向量命中或查询异常时，仍直接保留原始 BM25 排序和分值，不做结构提权或限流；向量查询原文、Top-K及缓存不变，候选上限由每路12扩大至20。

### 回答表达与上下文预算

已实现：提示词入口为 `ChatService._run()`，没有新增 `answer()` 方法。系统要求清晰实用的回答，追问最多两项，只问影响定性的关键客观事实，禁止无关个人隐私、男女关系细节及在追问句末标注 `[M1]` 等编号。只有正文具体依据句标注材料编号，写明法律名称和条号，如“依据《中华人民共和国教育法》第四十三条[M1]”，不能用“[M1]第四十三条”代替法名，条号必须与所标材料一致。

`## 处理方向` 不只复述罪名或抽象条款，而须结合材料按先后顺序分条写实操步骤。第一步立即止损、保护现场并固定证据，保留原始记录、书面通知、监控与物证线索、截图和时间，或要求平台/对方停止侵害。第二步随场景变化：合同/消费争议与对方或平台交涉；仅在明确属于用人单位或校园纠纷时向内部机构书面反映、申诉或切割自身责任；街头侵害、治安或刑事案件先脱险、就医验伤或梳理客观时间线。原固定内部机构举例已移除，系统明确“严禁在无关场景生搬硬套单位法务、教务处、学生申诉委员会或员工手册”，这些名称只出现在禁令中。第三步分情形行政投诉、民事/行政起诉、向公安机关报案及在调查中如实陈述、申请调取客观证据，或依法委托辩护人。机构权限或受理条件材料不明仍须核实，不自动认定管辖、诬告成立或要求每个问题走全部途径。

复合场景要求：涉及项目、技术或机密时，将权利归属（个人成果还是单位职务作品）、保密措施及双方具体操作经过合并在上述最多两项追问内。若他人窃取、擅自公开、欺诈与提问人自身操作或疏忽并存，必须双向兼顾：既说明追责与维权途径，也提示自身合规风险、止损和取证措施，包括核查联网信道、未清理敏感内容等环节。该要求设置在现有 `_run()` 的 `system` 中，未新增 `ChatService.answer()` 入口。

四个标题的顺序、仅依本轮材料、条件不足用“如果/可能”、期限须有主体/起算条件/材料编号及不抄条文等约束继续保留。末尾单独写 `USED_IDS:`，列齐实际编号；无材料时写无，不得编造。原始模型漏声明仍计入评测；本轮新增合法正文唯一绑定补齐，可消除已解决的漏声明提示，不能放行未知编号或错条号。

材料相关性自检：引用前须核对材料适用场景与主体是否同问题一致，严禁将场景不符的条文强行套用。若全部候选均不直接对应所问具体情形，须在“不确定性”说明本地资料未直接覆盖该专门情形，只给通用取证与核实步骤并声明 `USED_IDS: 无`；不能为凑编号套用邻近领域条款。此时三步指南也受“仅通用取证与核实”的限制。该护栏是传给模型的系统规则，未新增确定性场景判定器，亦不触发地域范围降级的 `scope_degraded` 标志；已有原始引用、期限检查及展示清理顺序不变。

展示清理：`postprocess(raw)` 先查原始编号/法条，再安全补有效声明；`deadline_grounding_issues()` 与 `amount_grounding_issues()` 只借已经核验的编号核对期限、赔偿倍数和确定金额，正文和 raw 不改。材料里没有“三倍”“十倍”或该元数时整段拦截，不展示生成结论。用户原话里的金额可以复述；倍数即使用户问到，也必须出现在所引材料中。所有校验及场景路径护栏通过后才调用 `clean_display_answer(raw, materials)`。解析、正文引用、法条绑定和展示共用 `USED_IDS_RE`，支持无冒号/空格及大小写变体，保留声明前标点、段落和后续行；左右标识符边界防止误吞普通变量。已知裸编号可补法名，方括号/括号编号静默清理；未知编号不能靠展示清理洗白。`raw_answer` 始终独立保留，原始模型漏声明与系统补齐记录分开，拦截时不展示问题正文/卡片。

650 汉字是输出篇幅建议，不是放宽输入预算；`size()` 仍将系统消息、历史和材料的 UTF-8 字节加消息开销一并计量。材料按 6800 字节目标线整条选取，最终消息不得超过 7000 字节。多轮装配顺序是“系统提示 → 历史视图 → 本轮材料包”：先按原规则装材料，再用余量倒序装历史，余量不足时从名次最低的材料回吐但至少留一条完整条文；助手旧回答在装配时压成一行正文，`Session.history` 本身仍存全文。超长输入不再抛异常，依次按“丢历史 → 截断送模问题副本 → 材料回吐到一条 → 无材料追问”降级。

会话底座（第 2 步）：`ChatService.start()` 先把用户原话异步追加到 `data/sessions/{sid}.jsonl`（`asyncio.to_thread` + flush/fsync），回答完成、被拦截、超时或出错都再追加一条回答事件；`read_events()` 跳过末尾半截行，`delete_session_archive()` 支持主动删除。`_recall_history()` 只读用户发言，按“明显指代，或与本轮问句高度词面重合”触发，最多注入 2 条 `【前情陈述（第N轮用户原话）】：“……”`，单片 ≤200 字节、合计 ≤500 字节，放在本轮用户消息而不是 system；指代模糊时不注入，留给“## 追问”。当轮实际注入的原话会拼成 `context_question = question + " " + recalled_user_text` 传给 `deadline_grounding_issues` / `amount_grounding_issues`，避免用户第 1 轮说的“5 万元”在第 5 轮被误判成捏造；`answer_scenario_issues` 与检索问句仍只看本轮问题。

### 官方白名单目录维护与问答兜底

**第一块：离线维护与版本盘点（已实现）。** `expansion_batches.find_catalog_updates(catalog_entries, indexed_records)` 是纯函数。调用方先从官方目录JSON取 `entries`，再传入本地记录元数据；本函数无网络、文件写入或向量副作用。它兼容国家库 `bbbs/title/gbrq/sxrq/sxx/flxz` 与行政目录 `url/title/publication_date/effective_date`，输出统一 `official_url`（同时提供 `url` 别名）、公布/施行日期及 `bbbs` 等字段。

目录有 `sxx` 时仅接受3（兼容字符串3），并排除明确的草稿、废止、失效标题/状态。显式URL均须通过校验，不允许恶意URL靠合法 `bbbs` 回退伪装；无URL但有 `bbbs` 时构造国家库详情链接。法名只整理空白、书名号和全半角，不抹掉解释序号或试行限定。日期支持明确年月日、ISO日期；同名本地多条按对应日期最大值比较：完全缺失为 `MISSING_FROM_LOCAL`，官方公布或施行日期明确晚于本地对应日期为 `VERSION_UPDATED_ON_OFFICIAL`；日期相同/更旧不列出。缺少本地可比较日期不推定官方更新，也不能据“未列入”认证已经最新。已公布待施行版本可用于维护盘点，不能由该结果直接发布为现行依据。

调用关系：取得新的官方目录 → 纯函数盘点 → 人工/维护流程确认范围与时效 → 既有官方原件采集、审计、发布 → 显式更新本地索引。盘点不会替调用方刷新旧目录，目录日期只是来源元数据，不是正文及法律适用审查。

**第二块：在线问答最后兜底（已实现，按入口区分默认行为）。** `ChatService(retriever, model, official_catalog=None, official_fetcher=None)` 仍默认不配置抓取器；直接构造默认离线，`create_app(service=...)` 保留该服务原配置、不自动绑定。默认 `create_app()` 在启动阶段显式绑定 `fetch_official_npc_slice`，匹配缺失专项时可能请求国家库；普通高分且无缺口问题不触发。目录仍只读 `data/catalogs/official-20261020/npc/judicial/catalog.json`，首次缓存，空列表可关闭匹配。更新目录后须重启服务或清缓存，不因问答自动改目录。

`match_official_whitelist_catalog(question, catalog_entries, indexed_titles, top_k=2)` 先排除不安全、非现行标记与已入库法名。原问句或明确口语扩展须连续四字命中去套话后的主题，原词与扩展词并集须至少重合3个双字词、覆盖标题主题词至少25%；原问句词项另加权，避免部分原文命中反而阻断完整扩展。新增“具体应用法律/具体适用法律”套话剔除，程序模板不能单独触发。最高返回两项，同名不重复，远低于最佳匹配的结果不附带推荐；这不是全文语义或个案适用判定。

口语专题包括：刷脸/人脸识别，拆封不退/七天无理由/直播带货/网购，退一赔十/过期食品/变质食品/假药，逾期交房/延期交房/逾期办证/一房二卖/买期房，财产保全/冻结账户/查封财产，微信聊天记录/电子证据/录音证据，以及立案标准/多少钱立案/够判刑吗/够刑事立案吗，共25个入口，均追加法定词与目录专题短语。给定24个入口外补背景原句“被骗五千块够刑事立案吗”的精确触发。泛立案口语虽然在BM25中补充诈骗、盗窃两类词串，目录联网仍要求原问句有该类行为线索；强奸、故意伤害或未说明类型的立案问题不能因此抓取诈骗/盗窃解释。该线索约束有限，不识别所有否定和复杂语义，模型仍须核对场景。

触发次序：先原本地检索，再执行境外/国内地方补贴硬降级检查；硬降级时不调用目录匹配/抓取器。其他请求只有明确匹配未入库专项才有兜底候选，原因分别记录为 `LOCAL_EMPTY`、`LOW_LOCAL_CONFIDENCE`（词面最高有效分<35、混合最高有效分<0.045）或 `MISSING_SPECIAL_TOPIC`（即使局部本地命中高分，仍明确命中缺失专项）。高分且无缺失专项时只做内存目录判断，无额外网络请求；不是低分就开放全网搜索。

配置 `official_fetcher` 时契约仍为 `await official_fetcher(entry, query)`。默认国家库适配器不把 `query` 发到官网或写入缓存，只在本机用于选条；第三方自定义适配器也须核验响应、版本、重定向和访问限制，不能擅自保存咨询。服务每项等待限时10秒、最多两项，未来日期只提示；失败/超时无切片时仍可给目录定位。取消不继续写回答历史；但阻塞采集通过 `asyncio.to_thread` 执行，停止等待不能强行终止已运行的后台线程，线程可能继续完成该版本的独立缓存，不能据此宣称全部网络活动立即停止。

**默认国家库适配器（已实现）。** `fetch_official_npc_slice(entry, query, *, cache_root=None, client_factory=PublicClient)` 只接受具有现行目录标记、明确日期、32位十六进制 `bbbs` 的国家库详情。入口及缓存 `record.url` 都核对同一版本的 `id/bbbs`，重复、空值或冲突参数拒绝。默认写入 `artifacts/local-rag/official-fallback-cache/<bbbs>/`，禁止将缓存根设在 `data/` 内；每版本同进程串行，不发布、不向量化。

1. 若版本缓存已有记录，要求 `PARSED`、身份/日期对应、原件与 `articles.json` SHA256一致、正文条号对应且连续、末条边界与数量一致。坏缓存或隔离状态返回目录定位，不隐式覆盖损坏文件。
2. 缓存缺失时只读固定 `data/catalogs/judicial-next-20261022/local-batch-p0-stage1/acceptance_summary.json`，按 `npc_bbbs` 查验全部验收检查、标题、版本、原件/解析哈希与数量后复用相应 `documents/`。现有状态 `PARSED_ISOLATED_PENDING_ADMISSION` 仅凭该处明确验收可只读临时选条，不能当作已经入库或修改准入状态；无来源URL时仅在内存补已核对的NPC详情链接。
3. 无可复用资料才在线程调用原 `capture_npc` 与 `PublicClient`，沿用详情标题/日期/`sxx==3`、DOCX解析及访问限制持久化。客户端和采集发生写入前，先检查原件、JSON、capture元数据、原子保存 `.tmp` 及根访问限制文件，拒绝路径逃逸、符号链接、硬链接和非普通文件；不在事后发现写穿才拒绝。
4. 对完整条文用扩展问句BM25选最高分单条；没有重合则返回第一条，该回退不证明场景相关。切片版本标注“官方白名单实时补充，现行性待核对”，来源为经过身份核验的国家库详情，后续仍经服务材料校验与预算。缓存命中不会重新联网确认现行性；异常、访问限制或非PARSED结果均不伪造正文。

来源校验仍通过 `public_url()`：默认调用只允许原 `ALLOWED` 主机；目录/兜底显式 `allow_government=True` 才另允许 `.gov.cn`（包含法院官方子域）的HTTPS来源。身份信息（包括空账号）、控制字符、非443端口、伪后缀和非官方地址均拒绝。返回切片还须法名对应、起始条号与 `locator` 一致、条号后存在实际正文；可提供的最终URL/重定向链也核验。单凭URL与文字不能认证实际响应真实，抓取适配器真实性仍是信任边界；服务不从用户问题抽取任意网址供抓取。

有效切片并在本地候选末位，统一标注 `官方白名单实时检索补充；已核验官方来源与条号，未独立复核个案适用`，按相同3600字符及6800/7000字节预算整条选择，仍走原始引用/期限检查。补充不发布、不写向量、不改法规快照。`official_fallback` 每项提供标题、公布/施行日期、官方链接、触发原因、`article_sources`、`material_ids` 与 `sent_to_model`；抓取成功但预算排除时也不能声称已提供引用。未配置或失败时仅返回安全目录定位信息，并在 `gaps` 说明本地全文未收录、未从非官方站点抓取，不编造正文。

### Web声明自愈、复合覆盖与刑民路径护栏

**阅读入口（已实现）。** 先看 `citation_check.USED_IDS_RE/parse_used_ids/body_material_ids`，再看 `postprocess()` 的原始检查与声明补齐，最后跟 `service._run()` 的场景硬拦、期限核验和展示分支。`used_ids` 现在是有效编号，`original_used_ids` 保留原声明；`declaration_repair` 提供 `repaired/body_ids/effective_used_ids`，`normalized_answer` 只供后续核验，`answer/raw_answer/modified` 的原始输出契约不变。卡片 `id_source=BODY_REPAIRED` 不冒充模型自行声明，也不计模型逐字引用成功。

`body_material_ids()` 仅接受本轮存在的显式编号，或唯一到一张卡的法律名称/简称+条号；只写法名且本轮有多条同法、同条多版本/多卡时不猜材料编号。所有声明行统一解析，末尾隐藏的未知编号仍硬拦；无材料仅声明M99也不能通过底层编号检查。省略冒号、空格、M前缀只在声明区容错，正文普通数字不是材料ID。普通 `USED_IDS_DEBUG/MY_USED_IDS` 变量不被当声明。伪示例、未知法名/条号不能靠补齐变通过；合法期限可用唯一绑定的有效ID核对，虚构期限仍拦。
