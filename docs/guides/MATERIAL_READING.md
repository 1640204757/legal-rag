# 回答许可：材料阅读与事实核对

## 本轮目标与边界

问题是“检索到一条真实法规，却把它当成提问人的确定结论”。条号、期限、金额在材料里出现，不证明主体、时间、其他要件及例外成立。当前阶段收紧允许展示的回答，不让程序冒充法律适用判定器。

本轮只改回答提示和放行许可。不改检索词表、公式、分数、阈值、每路20的池深、主检索默认4、展示前8与尾部，也不扩大3600字符和6800/7000字节预算。已有未提交的金额/倍数检查及前端改动保留；实施前的8个文件原样快照在项目内 `artifacts/local-rag/material-reading-experiment/preexisting/`，不作为公开分发资料。

## 已实现并接入的许可函数

主阅读入口：[answer_permission.py](../../local_rag/answer_permission.py) 的 `material_reading_issues()`。

- 四个标题保留，逐行检查整份原始回答，不仅检查“处理方向”。
- 原文格式为 `材料[M1]原文：“对应材料的完整句。”`。只去掉排版空白、允许省略纯条号/列项序号及末尾句号，不替换其他词。按原文起止边界核对完整段落或连续整句；不按逗号或分号截掉前提，不能改“应当”为“可以”，也不把小数误当成列项编号。
- 核实问句格式为 `材料[M1]中的“原文连续片段”是否符合实际情况？`。片段必须在对应材料里，最多两项；无合适线索用固定的通用事实问题。它是AI挑选的核实线索，不是完整、必要或充分的法律要件清单。
- 通用行动仅放行明确列出的保存已有记录、核对官方版本/主体/条件/例外、向官方机构或执业律师核实等固定表述。
- 除原文节选、来源要素问句及固定提示外，未知自由文字整段拒绝。肯定结论、否定结论、换词结论、“如果”包装的个案建议、其他标题内偷带结论、声明内夹带结论均无许可。不是通过“应当/构成”禁词判断，原文一般规则里的这些字可以保留。
- 用户补充或自称条件齐全也不解锁个案结论。模型原始回答保留，不删除错误句后再说通过；失败不写入助手会话历史。

自由转述是否改变法律含义，词面程序无法证明。因此本模式直接限制为可逐字核对的节选，不把任意自然语言概括认证为“忠实转述”。原文全文仍在条文卡片/检索候选中；即使完整句匹配，也可能缺跨句、跨条或其他法规的例外，不能声称消除了所有误用风险。

## 调用关系与预算

`ChatService._run()` 仍用原检索及材料预算。有候选材料时使用 931 字节的 `MATERIAL_SELECTION_SYSTEM`（模型只输出 `SELECT:`/`ASK:`，不抄原文和排版）；无材料时仍用 1790 字节的 `MATERIAL_READING_SYSTEM`，保持 `no_materials` 单轮快照逐字节不变。选择提示更短，但材料原文仍完整送入；最终回答的原文、四段标题、固定步骤和 `USED_IDS` 由 `build_final_answer()` 从材料内存原文回填。来源编号通过校验后才由展示清理补为实际法名，不让“材料原文”失去来源身份。具体实际送模覆盖另按真实输入检查，不能因提示变短就断言覆盖必然改善。

原始回答继续经过 `postprocess()` 的引用/条号校验、`answer_scenario_issues()`、期限与金额检查，然后才加上阅读许可检查。任何硬错误都保持整段拦截、引用卡片清空，候选原文仍可查看；通过后才运行展示清理。`raw_answer`不改写，新增的阅读模式标记/说明只说明产品边界，不证明适用。

## 2026-11-07：程序切句、模型选号、程序回填

这一轮解决的是“原文抄写”这一类错误，不是法律适用判定。根因是 4B 同时做四件事：判断哪条材料相关、逐字摘录、写成来源问句、按固定标题排版。只要其中一步抖动，就会出现删前提、改标点或把提示说明抄进回答。

### 职责怎么分

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| 程序 `split_source_excerpts()` | 按 `is_complete_source_excerpt()` 的合法起止边界，把每条材料切成 `M1#1`、`M1#2`…；每段单独复检 | 不判断材料是否适用于提问人 |
| 模型 | 只输出两行：`SELECT: M1#2, M2#1` 或 `NONE`；`ASK: 原文连续短语 | …` 或 `NONE` | 不抄原文、不写标题、不排版、不生成 `USED_IDS` |
| 程序 `assemble_answer()` | 按编号从材料内存原文回填 `材料[M1]原文：“……”`、四段标题、固定两步和 `USED_IDS` | 不改写原文、不补法律结论 |
| 原校验器 | `postprocess()`、`answer_scenario_issues()`、期限/金额检查、`material_reading_issues()` 对装配后的最终回答逐项复核 | 没有放宽任何一条 |

模型仍可能输出旧的完整阅读格式。旧格式本身合法时原样放行（`passthrough`），保证既有空格/标点逐字节不变；完整旧格式抄错时不自动修补（`structured_invalid`），仍按原规则拦截，避免把抄写错误“洗”成通过。只有“全部由材料行组成、但缺四段标题”的自由文本，才按材料编号和子串定位回完整合法原句后装配（`recovered`）；夹带自由结论或提示说明的文本不恢复（`unparsed`）。编号不存在或完全无法解析时不猜号，返回原始输出交给原校验器拦截。

### 已知边界：交叉引用选段会被弃选

`article_grounding_issues()` 要求回答里出现的每个条号都能绑定到本轮材料的 `locator`。像“第二十七条……违反本条例第八条……”这种同一部法内部的交叉引用，材料 locator 是“第二十七条”，现有校验器无法把它绑定到“第八条”。本轮不修改校验器，也不往原文里插编号或改标点，而是让装配按原顺序保留尽量多、且能通过原校验器的选段；被弃选段写进 `answer_assembly.dropped` 供审计。若全部选段都无法通过，仍返回原始输出并拦截，不猜号、不放宽。

这不是“自动修好旧格式”：完整旧阅读格式若本身抄错，仍然拦截；D0406/D0903 的改善来自新选择提示从源头避免逐字抄写，不是靠事后洗白。

## 大白话与已知缺口

原来程序能核对“这条法规、这个数字确实存在”，仍不能证明“这条就该用在这个人身上”。合成测试和真实回答中的删前提节选暴露了这层缺口。本轮把出口收紧为可对照的原文、核实线索和通用步骤；自由个案结论即使引用正确也拒绝，用户补充事实也不自动放行。

代价是回答范围缩小，部分问题只能看候选或补充事实；仍有3/20生成格式/摘录失败被拒绝，核实线索也可能不够具体。未认证法规现行性、材料相关性、事实真伪、清单完整性或法律推理正确。更强模型、检索贴题门控和任意自然语言转述的语义核验不在本轮实现范围。

## 2026-11-08：次选异法专门条例过滤（15 日与六个月并存已收口）

**问题。** 模型按 `SELECT` 选了两段，两段来自不同法律：首段是通用大法（《行政诉讼法》第四十六条“六个月内提出”），次段却是用户没提过的专门条例（《村庄和集镇规划建设管理条例》第四十四条“十五日内起诉”）。结果同一份回答同时给出两个互相冲突的期限。D1203（行政处罚法 + 道路交通安全法实施条例）、D1102（刑法 + 铁路法）属同一类。

**改哪一层。** 只改装配层：`answer_assembly._drop_unsolicited_secondary()`，`build_final_answer()` 增加可选 `question`，`service.py` 一行传参。提示词、模型、检索、排序、阈值、池深、送模条数都没动；`answer_permission.py` 与三个校验器一字未改。

**怎么判断。** 三条同时满足才弃选次段：① 次段与首段不是同一部法；② 次段法名去掉“中华人民共和国”“实施条例/管理条例/条例/办法/法典/法”等通用头尾后，还剩 ≥2 字的专门主题核心（基础法和司法解释在此直接返回空串）；③ 用户原问句里找不到该主题的线索（核心整体、核心的任意 2 字片段、或 `_DOMAIN_HINTS` 里的常见同义说法都没出现）。两段期限数值不同（六个月 vs 十五日）时，弃选原因记为 `period_conflict`，否则记为 `unsolicited_special_law`，统一写进 `answer_assembly.dropped`。

弃选前还要确认首段单独装配就能通过原校验器，所以**弃选不会把一份本来合格的回答变成拦截**。没有问句参数时规则完全不启用。

**为什么不会误删正确引文。**

- 同一部法选两条（民法典第一千零六十三条 + 第一千零六十五条）：法名相同，保留。
- 基础法 + 司法解释（民法典 + 民间借贷规定；行政诉讼起诉期限解释）：司法解释标题命中“最高人民法院”，保留。
- 消保法 + 消保法实施条例：两者都在基础法白名单，保留。
- D0607“出车祸”：次段是道路交通安全法，问句含“车”“车祸”，领域线索命中，保留。
- 问句确实提到专门领域（D0903 酒店摄像头 → 公共安全视频图像）：单条选择本就无需过滤，提到时也会保留。
