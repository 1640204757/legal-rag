# 当前口语检索与小模型回答的根因定位

日期：2026-11-03。目标是使用明确指定的现成模型、公开的程序与可复现环境，不训练或蒸馏私人模型。本轮完成诊断和诊断工具补充，**没有宣称问答问题已修复，也没有采用新的生产提示或检索策略**。

## 已经确定的结论

问题发生在不同环节，不能统一解释为“4B参数小”或“提示词多”。

1. **检索是已经确认的前置瓶颈。** 当前dev80题，51题至少一个目标进入前4；剩余29题中，15题在合并候选里却没进前4，7题在某一路第21–60名但没进池，7题在两路前60都没有。回答模型尚未参与，不能靠修回答提示解决这些漏检。0.38阈值挡掉的题为0。
2. **词表依赖真实存在，但整体关闭会退步。** 当前词表有207个触发键、78份不同的右侧扩展文本。关闭整表及依赖它的锚点后，dev前4从51降到34，holdout从13降到12；说明它在补偿现有通用检索的不足。不能把这解释为每个词都合理，也不能据此继续无上限堆词。
3. **旧版提示挤占材料，不再是当前dev的主要损失环节。** 当前系统提示1790字节，dev实际送模目标51/80，与前4的51/80一致；逐题核对无已命中目标被预算丢弃。历史3320字节提示下的43/80不能用于解释当前版本。
4. **当前4B在材料齐备时仍有可复现的指令执行/摘录失败。** 三条已知失败重新执行真实推理，输入和错误输出均与旧证据逐字相同。它们没有发生输入容量或输出长度截断。一版更短的提示也未让三条通过，不能简单断言“再精简几句就能解决”。

这些证据定位了发生故障的边界；尚不能证明模型参数规模是唯一原因，也没有证明换大模型必然解决。尤其不能把三条定向失败复现当成总体错误率。

## 后续修改应该解决什么

1. 检索方面，把“语义/词面未召回”和“已经召回却排不上”作为独立问题。若想减少207项口语触发规则，需要先有不依赖这些触发词的召回/排序替代证据；不能直接移除后让4B凭记忆补答案。
2. 回答方面，优先重新划分模型和程序的职责：完整原文、来源、固定提示和排版具有确定性，不应继续主要依赖模型逐字生成。可研究模型只输出受限的材料/片段选择，由程序引用原始文本；这仍需要验证相关性选择、条件完整性与未知编号拒绝。**该方案已于 2026-11-07 实现并通过定向真实 4B 复测与 20 题 dev 抽检**：程序按 `is_complete_source_excerpt` 切句编号，模型只输出 `SELECT:`/`ASK:`，`answer_assembly.build_final_answer()` 从材料原文回填，原有全套校验器继续核对最终回答。职责对照、三道原失败题复测和已知边界（交叉引用选段会被弃选）见 [材料阅读许可](MATERIAL_READING.md#2026-11-07程序切句模型选号程序回填)。这证明的是抄写环节被移到确定性程序，不是法律适用正确。
3. 不把“是否找全”和“是否适用”的最终决定全部交给当前4B。多轮搜索只有在查询生成与缺口识别分别通过测试后才考虑接入；已有口语改写失败见[独立试验](QUERY_REWRITE_EXPERIMENT.md)。
4. 公开验收要包括独立新问法、同模型/同语料、实际材料和原始回答。现有`expect_any`命中率及单元测试通过不能证明“普通人所有问法都能找全”。另机部署验收仍按[开源准备记录](OPEN_SOURCE_READINESS.md)执行。

以上是基于证据的修改方向，不是已经完成的功能或效果承诺。根因仍需在具体可复现子问题上继续验证，不能把“位置找到了”说成“所有原因已查清”。

## 2026-11-04：下一处该改什么——先补“相关性重排”，不再加词

状态：只做复测、只读探针和路线设计；**生产检索、词表、阈值、提示和数据库均未改变**。下面是“已验证”的测量结果和“待验证”的实施建议，不能当作已上线效果。

### 本轮已验证的两件事

1. **当前生产基线可复现。** [复测](../../artifacts/local-rag/measure-runs/20261104-133038-495687/summary.json)与11月3日基线比较，dev、holdout、v2的前4/前8快照变化数全部为0：仍为51/61、13/16、36/36；156题均正常混合检索、无异常，耗时154.16秒。`local_rag/retrieval.py`哈希与上一轮一致。
2. **“把问句拆成短句做多路语义召回”没有效果，不采用。** 只读探针把每道题按标点拆成平均3.33个短句，分别向量化后按两种方式合并，再对照整句向量：

| --- | --- | --- | --- |
| dev 80 | 29 / 43 / 52 / 59 | 23 / 28 / 46 / 56 | 26 / 35 / 46 / 60 |
| holdout 40 | 11 / 15 / 18 / 24 | 7 / 11 / 15 / 22 | 7 / 12 / 16 / 22 |
| v2 36 | 33 / 35 / 35 / 35 | 26 / 29 / 32 / 34 | 33 / 33 / 34 / 34 |

整句一列与生产语义路完全一致，说明探针口径可用。分句在dev、holdout、v2的前4都下降或持平，因此**不能靠“换一种问法/多切几段”解决口语检索**。证据目录：`artifacts/local-rag/dense-facet-probe/runs/20261104-133337-664554/`（只读，不随Git公开）。

### 数据把问题指到了哪里

29道dev未命中里：

- **7道两路前60都没有**（D0305、D0509、D0609、D1007、D1009、D1203、D1209）。例如“接到处罚四个月了……再去法院会不会太晚”对应行政诉讼法第四十六条的六个月起诉期限；问题里没有“六个月”“起诉期限”这些词。这类是法律概念缺口，加同义词或换排序都很难稳定解决。
- **22道已经找到，只是没进前4**。其中12道的正确答案语义排在第5–20名，6道在第21–60名，2道本来就在前4附近却被融合分挤下去。
- 典型是“差一条”：D0203“地板正常磨旧了房东非扣钱”，正确条文民法典第七百一十条语义第5，前4里是第七百一十一条（承租人**未按约定方法**使用）等相邻条文；D0303“借人两万没提利息”，正确条文第六百八十条语义第3，前4全是民间借贷司法解释的相邻条款。

这说明：**语义模型大致知道在说什么，当前融合公式却不会判断“这几条里哪一条才是正面回答”**。现有分数基本只由名次和固定倍率决定，相似度0.691和0.684在公式里没有区别，所以无法把“正常磨损不赔”和“未按约定使用要赔”分开。

### 建议的实施顺序（一次只动一处）

**第1步（建议先做）：加“相关性重排”，把召回和判断分开。**

- 召回不动：语义、扩展词面两路继续各取候选；建议同时把语义候选看到第60名（Qdrant单次60条实测约24毫秒，代价很小）。
- 重排新增：用一个现成的中文/多语重排模型（cross-encoder，例如 bge-reranker、gte-reranker 一类）对“问题 + 候选条文原文”逐对打分，取前4/前8。它读的是原文，不依赖207项触发词，也不改写用户问题。
- 先做独立实验，不直接上线：冻结当前生产结果作对照，用同一批dev/v2/holdout比较前4、前8、MRR，并逐题列出“新进前4”和“丢掉的原命中”。
- 上线门槛建议：dev前4明确高于51；dev前8不低于61；holdout前4不低于13；v2保持36/36；原命中不得出现未解释的丢失。任一条不满足就不接生产。
- 代价要如实说明：本机无NVIDIA GPU，重排模型在CPU上会增加单题耗时（预计数秒级，需实测），并且要新增可选依赖和模型文件；没有配置模型时必须自动退回当前逻辑，不能让网页起不来。

**第2步：重排有效后，再给词表“减肥”。**

现在有14道dev命中是“语义没找到、只靠扩展词面找到”的，说明词表仍在补召回。重排上线后，按词组做消融：每次只关一组，观察这14道能否由更深召回或重排接住。能接住的就删，接不住的保留。目标不是把207项清零，而是让词表只做“召回补丁”，不再承担排序。

**第3步：单独处理7道“两路都没有”的概念缺口。**

这类问题不适合继续加单题长句。可选方向：建立一个**法律概念索引**（概念名 + 规范定义句 + 相关条文），用条文自己的规范句做入口，而不是开发者手写口语触发词；或者在确实找不到时明确提示“可能涉及起诉期限/工伤认定申请期限等，需要补充事实”，不要硬答。是否值得做，要先用这7道题单独验证概念召回，不能拿总体命中率掩盖。

**第4步：回答侧维持“程序引用原文”。**

现有材料阅读许可已经把自由结论挡住，方向是对的。重排只决定“送哪几条”，完整原文、来源、固定排版仍应由程序拼装，不让4B逐字生成。

### 这一轮明确不做什么

- 不再按单题加口语词、法名或阈值；已有整表关闭和扩池实验都证明会退步。
- 不把“拆句/改写问句”当成通用解；改写已有20题真实失败记录，拆句本轮也为负结果。
- 不把“前4命中51/80”说成“口语已经解决”。它只表示至少一条目标条文进了前4，不代表找全、也不代表适用。
- 不把重排模型直接接进网页默认路径；必须先过上面的独立实验和快照门槛。

### 2026-11-04 补记：重排实验已做完，结论是负的
